Проверка выполнена через браузерную автоматизацию (Claude in Chrome) на
запущенном пользователем стеке `docker compose`.

```

порт, на котором открылось: 8080
ключ LLM задан (да/нет): да (/api/status → llm_configured: true)

ШАГИ            ПРОШЁЛ / НЕ ПРОШЁЛ / НЕ ПРОВЕРЕН
1 загрузка: ПРОШЁЛ
2 статус: ПРОШЁЛ
3 стриминг: НЕ ПРОШЁЛ (частично — стадии приходят, но контента нет)
4 цитаты: НЕ ПРОВЕРЕН (нет цитат — индекс пуст)
5 повторный запрос: НЕ ПРОВЕРЕН (заменяется только текст вопроса; цитат и
  подсветок не было, а именно они и есть предмет шага)
6 клавиатура: НЕ ПРОВЕРЕН (до цитаты не добраться — цитат нет)
7 граница 422: ПРОШЁЛ
8 консоль: НЕ ПРОШЁЛ

Для каждого НЕ ПРОШЁЛ — что именно произошло:

шаг 3: Ответ приходит, но пустой по существу. Стрим отдаёт четыре строки
  почти мгновенно (~1.6 с до первого байта, все три чанка в пределах 1 мс):
    {"type": "documents", "data": []}
    {"type": "progress", "stage": "extraction_complete", "elapsed_ms": 0}
    {"type": "highlights", "data": []}
    {"type": "answer", "data": {... "citations": [], "documents": []}, "done": true}
  В UI это «Based on the available documents: No relevant information found in
  the provided documents.» Постепенности не видно, потому что стримить нечего:
  ответ приходит одним финальным блоком.

  Причина: индекс пуст. GET /api/documents → {"documents":[]}. Ни
  `docker compose up`, ни README не содержат шага наполнения индекса, а
  POST-эндпоинта ингеста в api/app.py нет — есть только GET /api/documents.
  Milvus Lite стартует с пустым /data/index.db в томе milvus_data.

шаг 8: На каждый запрос в консоль падает по три предупреждения:
    Unknown response type: progress
  Источник — src/contexts/ApiContext.js:165: в `switch (data.type)` нет ветки
  для `progress`, а бэкенд её отдаёт (api/app.py:432-442). Это регрессия
  контракта между стримом и его потребителем.

ВОПРОСЫ

В1 повторный запрос: Текст вопроса и блок ответа заменяются полностью,
  остатков предыдущего нет, мелькания нет. Но это ничего не доказывает:
  ни цитат, ни подсветок, ни списка источников в обоих ответах не было, а
  правила `noArrayIndexKey` и `useExhaustiveDependencies` отключены именно
  из-за них. Шаг надо переигрывать на непустом индексе.

В2 клавиатура: Живьём — не проверено, активировать нечего. По коду
  (CleanFactInterface.jsx:171-182) `InlineCitation` — это
  `<sup role="button" tabIndex={0}>` с onKeyDown на Enter и Space
  (с preventDefault), то есть с клавиатуры активироваться должно.
  Замечание: фокус-стиль `focus:outline-none focus:ring-1 focus:ring-primary`
  даёт кольцо в 1px и вешается на `focus`, а не `focus-visible` — тонко для
  надстрочного элемента размером 0.65em. Проверять глазами обязательно.
  Второе замечание: onClick — `() => fact && handleFactClick(fact)`. Если
  номер в тексте не нашёл fact, элемент остаётся фокусируемым и кликабельным,
  но не делает ничего и никак об этом не сообщает.

В3 подпись у поля: ДА, дефект подтверждён эмпирически. В разметке есть
  `<label>Ask a question about your documents</label>` без `htmlFor`, у
  `<input>` нет ни `id`, ни `aria-label`, ни `aria-labelledby`. Клик по
  подписи оставляет фокус на `body`. Правило `noLabelWithoutControl`
  отключено обоснованно по факту, но чинится однозначно: дать инпуту id и
  проставить htmlFor. Решения о поведении UI здесь не требуется.

В4 нумерация цитат: НЕ ПРОВЕРЕНО. По коду номер берётся из литерала `[n]` в
  тексте ответа (remark-плагин, CleanFactInterface.jsx:192-224) и ищется в
  `facts` по `citationNumber`. Порядок задаёт бэкенд; фронтенд его не
  нормализует и не проверяет. Оценивать можно только на реальном ответе.

В5 сценарии для тестов (до трёх, по важности):
   1. Смена запроса при непустом индексе: после второго ответа в DOM не
      осталось ни одной подсветки, ни одного узла источника и ни одного
      номера цитаты от первого. Это ровно то, что закрывают отключённые
      `noArrayIndexKey` и `useExhaustiveDependencies`, и единственный тест,
      снимающий с них вопрос.
   2. Контракт стрима: каждый `type`, который отдаёт /api/query/stream,
      имеет ветку в ApiContext. Тест на текущем баге падает и не даёт
      добавить стадию на бэкенде, забыв про фронтенд.
   3. Активация цитаты с клавиатуры: Tab до `sup[role=button]`, Enter и
      Space — то же, что клик, фокус видим. Закрывает В2 и обе отключённые
      a11y-строки про роль на неинтерактивном элементе.

В6 прочее странное:
   - Главное: /api/status отдаёт resources_loaded: true при пустом индексе.
     Проверка в api/app.py:251 — `hasattr(rag, "index") and rag.index is not
     None`, то есть «объект существует», а не «в нём что-то есть». В шапке
     горит зелёный «Ready», при этом любой вопрос возвращает «No relevant
     information found». Это худший вид зелёного статуса: он не отличает
     рабочую систему от пустой. Стоит добавить счётчик документов в
     StatusResponse и показывать его в UI.
   - `<link rel="apple-touch-icon">` указывает на
     /chiliground-transparent.png — 917 КБ, грузится на каждой загрузке
     страницы. Иконка kr.svg рядом весит 14 КБ. Раз в этой ветке фавиконы
     всё равно переводили, touch-иконку логично было пережать или тоже
     заменить.
   - Кнопка Ask при пустом поле disabled и из tab-порядка выпадает — это
     корректно, но означает, что во всей стартовой странице ровно три
     фокусируемых элемента (лого, инпут, Ask) плюс карточки примеров.
   - README описывает docker compose как «development and demo stack», но
     демонстрировать на нём нечего: из коробки корпус не индексируется.
     Либо шаг ингеста должен быть в README, либо образ должен подниматься с
     предзаполненным индексом (в репозитории для этого лежит test_docs/).
