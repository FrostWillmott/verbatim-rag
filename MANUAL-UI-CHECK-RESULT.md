# Результат ручной проверки UI — ветка `audit-remediation`

Проверка через браузерную автоматизацию (Claude in Chrome) на стеке
`docker compose`. Прогон второй: первый упёрся в пустой индекс, здесь индекс
наполнен (README.md проекта + tiny.md), шаги 3-6 отыграны полностью.

```
ОКРУЖЕНИЕ
дата: 2026-08-27
порт, на котором открылось: 8080
ключ LLM задан (да/нет): да (/api/status → llm_configured: true)
браузер и версия: Chrome 151.0.0.0, macOS

ШАГИ            ПРОШЁЛ / НЕ ПРОШЁЛ / НЕ ПРОВЕРЕН
1 загрузка: НЕ ПРОШЁЛ (битая картинка маскота)
2 статус: ПРОШЁЛ
3 стриминг: ПРОШЁЛ
4 цитаты: ПРОШЁЛ
5 повторный запрос: НЕ ПРОШЁЛ (утечка highlightedFactId между запросами)

Для каждого НЕ ПРОШЁЛ — что именно произошло:

шаг 1: На стартовом экране вместо маскота — иконка битого изображения с
  alt "Chili Mascot". `img.naturalWidth === 0`.

  GET /chiliground-transparent.png → 200, Content-Type: text/html, 1096 байт,
  тело начинается с `<!DOCTYPE html>`. Это index.html: nginx.conf:22 отдаёт
  `try_files $uri $uri/ /index.html`, поэтому отсутствующий ассет возвращает
  200 с HTML, а не 404.

  Файл удалён из frontend/public/ коммитом 6432bee, но ссылка на него осталась
  в CleanFactInterface.jsx:529. Из index.html ссылку (apple-touch-icon) убрали
  корректно — пропустили только <img> внутри компонента.

  Отдельно стоит отметить механику: из-за SPA-фоллбэка проверка «нет 404 на
  статику» этот дефект не ловит в принципе. В консоли тоже пусто — ответ 200,
  сетевой ошибки нет, только неудачное декодирование. Ловится либо проверкой
  Content-Type, либо `naturalWidth`.

шаг 5: После второго запроса, без единого клика, в панели источников уже
  подсвечен фрагмент с активным кольцом (`ring-primary/30`) — как будто
  пользователь кликнул цитату.

  Воспроизведение (детерминированное, проверено с чистой перезагрузки):
    1. Перезагрузить страницу.
    2. Запрос «How do I put documents into the index?» → 3 цитаты,
       активных подсветок нет: activeRing = [], hlIds = ["0"].
    3. Кликнуть цитату [2] → activeRing = ["Documents are indexed using
       vector embeddings (both dense and sparse)"], hlIds = ["1"].
    4. Запрос «What does verbatim mean in this system?» — БЕЗ кликов.
       → activeRing = ["Property Built-in exact/static path Outside the
       guarantee Evidence text Returned…"], hlIds = ["0","1"].

  Причина, CleanFactInterface.jsx:58-65. `handleSubmit` сбрасывает
  `setSelectedDocument(0)`, но не сбрасывает `highlightedFactId`:

      await submitQuery(question);
      setQuestion('');
      setSelectedDocument(0);
      // setHighlightedFactId(null) — отсутствует

  `highlightedFactId` — это индекс в массиве фактов (`extractFacts`,
  `id: i`), а не идентификатор конкретной цитаты. Он переживает новый запрос
  и переприменяется к факту с тем же порядковым номером в НОВОМ ответе.
  Тот же пропуск в `goHome` (строки 67-71): «домой» гасит запрос, но
  оставляет подсветку.

  Почему это легко пропустить руками: утечка видна, только если в новом
  ответе цитат не меньше, чем был индекс. В моём первом прогоне активной
  была цитата [3] (id 2), а следующий ответ дал одну цитату — факта с id 2
  не нашлось, ничего не подсветилось, и шаг выглядел чистым. Ложноотрицательный
  результат зависит от числа цитат в следующем ответе.

  Это ровно та остаточная подсветка, ради которой шаг 5 в чеклисте и написан.

ВОПРОСЫ

В1 повторный запрос: Заменяется почти всё и без мельканий. Замер по DOM с
  шагом 120 мс на запросе «How do I put documents…» → «What is the difference
  between static and contextual template mode?»:
    t=0      3 цитаты, 5 вкладок, старый вопрос
    t=5679   всё снесено: 0 цитат, 0 вкладок, новый вопрос, текст 304 симв.
    t=6586   пришли документы: 5 вкладок
    t=9590   пришёл ответ: 1 цитата, текст 700 симв.
  Промежуточного состояния «новый ответ со старыми источниками» нет,
  старого текста, старых номеров и старых фрагментов не остаётся.

  Единственный остаток — `highlightedFactId`, см. шаг 5. Это не визуальный
  мусор от прошлого ответа, а состояние выделения, которое переносится на
  новый. Правило `useExhaustiveDependencies` тут ни при чём: сброса нет не в
  массиве зависимостей, а в обработчике сабмита. `noArrayIndexKey` — при чём
  напрямую: id факта это индекс, и именно поэтому старый id «попадает» в
  новый ответ вместо того, чтобы не найтись.

В2 клавиатура: ДА, цитата активируется только с клавиатуры.
  Реальный проход Tab (не эмуляция) с середины страницы:
    1. SUP[button] "Show citation 1"   outline: 2px solid
    2-6. BUTTON "README …" (вкладки)   outline: 2px solid
    7. BUTTON "KR Labs • Verbatim RAG" outline: 1px auto
    8. INPUT  "What would you like to know?"
    9. SUP[button] "Show citation 1"
  Цитата достижима, фокус видно (2px кольцо + box-shadow цвета primary).
  У элемента есть aria-label «Show citation N».
  Enter — подсвечивает нужный фрагмент и переключает вкладку документа.
  Пробел — то же самое, страница при этом не прокручивается (preventDefault
  работает).

  Замечание: после активации (и Enter, и Пробелом) `document.activeElement`
  становится `body`, хотя сам `sup` из DOM никуда не делся. Пользователь
  клавиатуры теряет место и следующим Tab начинает обход заново. Это не
  блокер, но чинится одной строкой и заметно меняет удобство.

  Кнопка Ask при пустом поле disabled и в обход не попадает — корректно.

В3 подпись у поля: НЕТ, дефекта больше нет. У `<input>` появился
  `aria-label`, `find` по странице видит поле как «question input textbox».
  В первом прогоне `<label>` без `htmlFor` оставлял фокус на `body` по клику
  — сейчас поле подписано.

В4 нумерация цитат: СООТВЕТСТВУЕТ. На ответе с тремя цитатами порядок в DOM
  [1], [2], [3] совпал с порядком появления в тексте, и каждая ведёт к своему
  источнику:
    [1] → вкладка 1, подсветка «index.add_documents([document])»
    [2] → вкладка 2, подсветка «Documents are indexed using vector embeddings
          (both dense and sparse)»
    [3] → вкладка 4, подсветка «Documents are indexed using vector embeddings»
  Во всех трёх случаях подсвечен именно тот текст, что стоит в цитате.
  На ответе с четырьмя цитатами номера тоже шли по порядку.

В5 сценарии для тестов (до трёх, по важности):
   1. Смена запроса сбрасывает состояние выделения. Кликнуть цитату [2],
      задать второй вопрос, проверить, что в DOM нет ни одного элемента с
      активным кольцом до клика. Тест на текущем баге падает. Обязательно
      брать второй ответ с числом цитат НЕ МЕНЬШЕ, чем индекс кликнутой,
      иначе тест зелёный по случайности — см. разбор в шаге 5.
   2. Цитата ведёт к своему источнику. Для каждой цитаты [n]: клик →
      выбрана ожидаемая вкладка документа И подсвечен фрагмент, чей текст
      совпадает с текстом цитаты. Это ядро продукта, и сейчас оно не
      покрыто ничем.
   3. Активация цитаты с клавиатуры. Tab до `sup[role=button]`, Enter и
      Пробел дают тот же результат, что клик; фокус после активации остаётся
      на цитате. Закрывает В2 и обе отключённые a11y-строки про роль на
      неинтерактивном элементе.

В6 прочее странное:
   - Битая картинка маскота, см. шаг 1. Главное здесь не сама картинка, а то,
     что SPA-фоллбэк nginx превращает любой отсутствующий ассет в 200 с HTML.
     Любая будущая проверка статики по кодам ответа бесполезна.
   - Панель источников: пять вкладок, все подписаны «README». Различить их
     можно только по бейджу с числом подсветок (1, 1, —, 1, —), а две
     вкладки вообще без подсветок — документы, попавшие в выдачу, но не
     процитированные. Пользователь не может понять, куда его переключили;
     заголовок чанка («Create index with providers», «How It Works»,
     «Data Flow») виден только после переключения. Заголовок чанка на самой
     вкладке решил бы это.
   - Счётчик «5 documents» считает чанки, а /api/status отдаёт
     document_count: 2. Два разных числа под одним словом «documents» на
     одном экране.
   - Цитаты [2] и [3] в первом ответе почти дублировали друг друга
     («Documents are indexed using vector embeddings (both dense and sparse)»
     и «Documents are indexed using vector embeddings»). Это качество
     извлечения, не дефект UI, но в демо выглядит небрежно.
   - Ассет `frontend/build/` — мёртвый каталог от старой CRA-сборки
     (`favicon-16x16.png` и `logo192.png` там нулевого размера). Docker
     собирает через vite и его не использует. Раз ветка занималась мёртвым
     кодом, каталог просится следом.
```
