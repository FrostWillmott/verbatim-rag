# Ручная проверка UI — ветка `audit-remediation`

## Зачем это нужно

Ветка меняла фронтенд, а UI ни разу не запускался человеком. Удалено девять
компонентов, провайдер контекста и мёртвый вызов загрузки ресурсов; заменены
фавиконы; поднят `axios`; в линтере **отключено шесть правил**, потому что каждое
требует решения о поведении интерфейса, которое нельзя принять, не потрогав его.

Твои ответы закрывают три вещи: подтверждают, что удаления ничего не сломали;
снимают или подтверждают отключённые правила; и говорят, какие сценарии стоит
закрепить тестами (`TST-4`, `CD-002` — единственная оставшаяся открытая строка
реестра).

Время: примерно 20–30 минут.

## Подготовка

```bash
cd <репозиторий>
git checkout audit-remediation
cp .env.example .env          # если .env ещё нет
# впиши ключ LLM в OPENAI_API_KEY
docker compose up --build
```

Открой `http://localhost:8080`.

Если в `.env` порт не задан — тоже 8080: значение по умолчанию сведено в этой
ветке. Если открылось на `80`, значит правка не подхватилась, отметь это.

Держи открытой консоль браузера (F12 → Console) на протяжении всей проверки.

## Шаги

### 1. Приложение загружается

Открой страницу.

**Ожидается:** интерфейс отрисован, консоль без красных ошибок.
**Отдельно посмотри:** иконка во вкладке браузера. Должна быть логотипом KR —
в этой ветке фавикон переведён с двух сломанных PNG на `kr.svg`.

### 2. Статус системы

**Ожидается:** интерфейс не сообщает об ошибке инициализации. Если ключ LLM не
задан, это должно быть видно **до** первого запроса, а не после.

Открой `http://localhost:8080/api/status` напрямую.
**Ожидается:** JSON с полями `resources_loaded`, `message` и `llm_configured`.
Последнее поле добавлено в этой ветке.

### 3. Запрос со стримингом

Задай вопрос по проиндексированному корпусу.

**Ожидается:** ответ появляется **постепенно**, а не одним куском; сначала
документы, затем текст ответа.

### 4. Цитаты

**Ожидается:** в ответе есть кликабельные номера вида `[1]`, `[2]`.

Кликни по каждой из первых трёх.
**Ожидается:** страница переходит к источнику, соответствующий фрагмент
подсвечивается, и подсвечен **именно тот текст**, который стоит в цитате.

### 5. Повторный запрос

Не перезагружая страницу, задай **второй** вопрос.

**Ожидается:** ответ и цитаты полностью заменяются. Ничего не остаётся от
предыдущего: ни старых подсветок, ни номеров, ни фрагментов источника.

Это самый важный шаг: он проверяет то, ради чего отключены правила про ключи
списков и зависимости хуков.

### 6. Клавиатура

Не трогая мышь, пройди по интерфейсу клавишей **Tab**.

**Ожидается:** фокус виден, и до цитаты можно добраться.
Дойдя до цитаты, нажми **Enter** или **Пробел**.
**Ожидается:** происходит то же, что по клику.

### 7. Граница запроса

Открой консоль браузера и выполни:

```js
await fetch('/api/query/stream', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ question: 'test', num_docs: 1000000 })
}).then(r => r.status)
```

**Ожидается:** `422`. Это граница, добавленная в этой ветке.

### 8. Консоль

Просмотри всё, что накопилось в консоли за проверку.

**Ожидается:** нет `Warning: Each child in a list should have a unique "key"`,
нет ошибок про несуществующие модули, нет `404` на статические файлы.

## Вопросы

Ответы на них решают судьбу отключённых правил линтера. Отвечай по факту
увиденного, а не предположениями.

**В1.** На шаге 5 — заменилось ли содержимое полностью и корректно? Если было
мелькание, задержка или остаток старого — опиши, что именно.

**В2.** На шаге 6 — можно ли активировать цитату **только** с клавиатуры?

**В3.** Есть ли рядом с полем ввода подпись, которая выглядит как заголовок поля,
но по клику на неё фокус в поле **не** попадает?

**В4.** Смотри на цитаты: их номера соответствуют порядку появления в ответе, или
где-то сбиты?

**В5.** Какие сценарии ты считаешь стоящими автоматического теста в первую
очередь? Назови не больше трёх, в порядке важности.

**В6.** Что в интерфейсе выглядит сломанным или странным, но не покрыто шагами
выше?

---

## Форма отчёта

Скопируй блок, заполни, верни целиком. Не переформулируй пункты — ответы
сопоставляются построчно.

```
ОКРУЖЕНИЕ
дата:
порт, на котором открылось:
ключ LLM задан (да/нет):
браузер и версия:

ШАГИ            ПРОШЁЛ / НЕ ПРОШЁЛ / НЕ ПРОВЕРЕН
1 загрузка:
2 статус:
3 стриминг:
4 цитаты:
5 повторный запрос:
6 клавиатура:
7 граница 422:
8 консоль:

Для каждого НЕ ПРОШЁЛ — что именно произошло:
шаг N:

ВОПРОСЫ
В1 повторный запрос:
В2 клавиатура:
В3 подпись у поля:
В4 нумерация цитат:
В5 сценарии для тестов (до трёх, по важности):
   1.
   2.
   3.
В6 прочее странное:

КОНСОЛЬ
Скопируй сюда все предупреждения и ошибки целиком, даже те, что кажутся
безобидными:
```

Скриншоты — по желанию, но для любого «НЕ ПРОШЁЛ» они экономят раунд уточнений.

## Если стек не поднялся

Это тоже результат, и его надо вернуть, а не чинить самому. Приложи:

```bash
docker compose logs api --tail 50
docker compose logs frontend --tail 20
```

и то, что показал `curl -fsS localhost:8080/api/status`.
